# Contributing

You can improve a specific result or implementation without endorsing the entire programme.

Useful contributions include reproducing an example, finding a counterexample, identifying prior work, clarifying a proof, implementing a model adapter, supplying a public dataset or proposing a discriminating experiment.

For a result, state the claim and assumptions, identify the source manuscript and version, and include the calculation or evidence. For an experiment, specify observations, interventions, outcomes, uncertainty and what would distinguish the alternatives. For software, provide a reproducible example and checks for the behaviour that matters.

Use the issue templates for a reproduction, counterexample or research proposal. Describe negative results plainly. Do not strengthen the status of a claim merely because code ran or an example was simulated.

Before opening a code change, run:

```sh
python -m unittest discover -s tests -v
```

The project will credit concrete contributions. Public materials should retain source attribution, and third-party content should remain under its original terms.
