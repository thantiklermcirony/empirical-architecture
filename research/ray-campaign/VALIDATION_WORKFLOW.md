# Linux validation workflow

Status: published and executed. [Run 34425598056](https://github.com/thantiklermcirony/empirical-architecture/actions/runs/34425598056) passes the paired real HTTP experiment, 13 new actor cases, all 16 existing LongPoll tests, one shutdown unit and applicable Linux hooks. Raw artifacts and an earlier invalid setup run are preserved in the evidence package.

The published workflow is `.github/workflows/ray-recovery.yml`; its companion files are in `research/ray-campaign/`. It triggers for changes under that campaign directory or its own workflow file, and also supports manual dispatch. The package includes the actual tested `candidate.patch`.

The runtime job uses Ubuntu 24.04 and Python 3.12. Both Ray's source and official native wheel are pinned to `80142bad1d1db176f19c7e3aff6b6448631e66c2`; the wheel SHA-256 is checked before installation. The source checkout includes Serve and `ray.tests`. Inspecting the actual wheel confirmed that it includes `_private/test_utils.py`, `_private/authentication_test_utils.py`, `_private/conftest_utils.py`, and `_common/test_utils.py`, but omits `ray/tests/conftest.py`. Therefore the job runs `setup-dev.py -y --allow serve`, followed by `setup-dev.py -y --allow tests`. Native/core and other Python modules retain the matching official wheel.

Dependencies are installed **once** before either experiment: the wheel's `[serve]` extras (including bundled `ray-haproxy`), plus explicit versions of pytest, pytest-asyncio, pytest-timeout, psutil and httpx, and explicit jinja2/numpy coverage for fixture imports. All resolved versions are frozen in the artifacts and stay unchanged between experiments. The inspected standard fixtures import httpx, pytest_asyncio and ray.tests directly. Optional Redis/server/browser test fixtures are not invoked by these selected tests, so their optional packages/services are not installed. The wheel's Serve extras supply requests, YAML support, gRPC, metrics and runtime-environment dependencies. The driver imports the actual standard fixture modules before testing; no conftest replacement or fixture stub hides missing dependencies. The pytest launcher imports and verifies the installed native Ray package before calling `pytest.main()`, with `--import-mode=importlib`. Import mode alone was insufficient: the earlier invalid run loaded the unbuilt checkout package during collection.

The driver runs the real HAProxy baseline, applies the candidate with `git apply --check` then `git apply`, runs the candidate, and compares their evidence in the **same virtual environment and checkout**. It never commits to or posts to Ray. A baseline failure does not prevent collection of candidate evidence; it does make the overall job fail. Source/module/native/HAProxy hashes, Python/dependency versions, actor identities, exact response bodies, logs and config state are preserved. The harness refuses mismatched paired runtimes and unfinished or crashed workers.

The candidate then runs `test_long_poll_reconnect.py`, the complete existing `test_long_poll.py`, and changed `tests/unit/test_*.py` files from the patch, each group in a fresh subprocess. This includes the proposed HAProxy manager shutdown test without invoking all unrelated HAProxy integration tests. All groups use the actual upstream conftest. Selected existing tests create their own session fixture locally in the disposable runner; no pre-existing cluster is contacted. CPU counts and fixture logic are not rewritten. Per-test and process deadlines keep hangs visible; the driver cleans only processes tagged by its own random run token.

The runtime job has a 30-minute limit and a 22-minute validation-step limit. Each HAProxy run has a 300-second internal watchdog and a 340-second driver bound. Test-group limits are 240 seconds for the new reconnect file, 360 seconds for the existing file, and 180 seconds for changed unit files, with a 90-second per-test timeout. These timeouts are failure gates rather than retries. Artifacts upload with `always()` after setup/test failure. A whole-job cancellation may still interrupt artifact upload; this workflow does not promise artifacts after infrastructure termination.

A separate 30-minute Linux lint job uses a full pinned source checkout so Serve type checking can resolve `ray.util` and other source modules missing from a sparse clone. It installs the repository-required pre-commit 3.5.0 and invokes the existing upstream hook IDs: buildifier, buildifier-lint, mypy (both configured entries selected), pyrefly-serve, docstyle, ruff (both entries), black, pydoclint, trailing-whitespace, end-of-file-fixer and check-ast. Each hook's real exit code and output is recorded; hook changes to candidate files fail validation rather than being treated as a passing submitted patch. This is an applicable-hook check, not a claim that every upstream CI target or the entire pre-commit configuration ran. The lint job never starts Ray.

The workflow requests only `contents: read`, uses no repository secrets, and disables persisted checkout credentials. Third-party action references are exact verified commits: [checkout](https://github.com/actions/checkout/tree/11bd71901bbe5b1630ceea73d27597364c9af683), [setup-python](https://github.com/actions/setup-python/tree/a26af69be951a213d495a4c3e4e4022e16d87065), and [upload-artifact](https://github.com/actions/upload-artifact/tree/ea165f8d65b6e75b540449e92b4886f43607fa02).

Interpret the results narrowly: baseline PASS means the catch-all stale-route failure was reproduced; candidate PASS means this single-node HTTP recovery contract passed. The job is green only if their comparison and every requested test stage pass. Missing results, timeouts, unhealthy deployment, replacement managers or a controller that retained its actor ID invalidate the proposed inference. Read `validation-summary.json`, `haproxy-comparison.json`, the JUnit XML files and `lint-summary.json` before describing the candidate as validated. No Kubernetes/GPU/vLLM/gRPC/autoscaling or whole-Serve recovery claim follows from these tests.
